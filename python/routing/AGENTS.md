### Selected gajaestack routing guidance

Read consumer-owned `.gajaestack/routing.toml` from the consumer working directory. These facts, scopes and policies belong to the consumer, not this installed dependency. Follow only explicitly selected components and conditional policies; installation alone activates no checks.

Keep quick iteration and completion distinct. Use `[fact].test_command` as the one completion command. Required checks run within that command only when the corresponding native pytest plugin or Bun test preload is actually configured. Inspect native wiring; a declaration is not proof of activation. Report selected but unbound checks separately rather than claiming completion covered them. This kit adds no runner or second completion path.

The optional `[fact].completion_timeout_seconds` is the consumer's outer completion budget, not a check timeout. The calling launcher must honour it and preserve failures and logs; an outer timeout means incomplete verification. Absence means unconfigured, not an invented default. The package does not alter launcher limits.

Use declared paths and the consumer's existing tools and harnesses. Missing prerequisites, empty scopes and failed native checks are not passes. For contributor feedback, suggest `gajaestack-python-check --reference-branch TARGET` or `bun run gajaestack-check --quick --reference-branch TARGET`, naming the actual contribution target explicitly, never guessing from tracking or `origin/main`. Mutually exclusive `--baseline-commit COMMIT` deliberately overrides merge-base selection. These lint current changed files since the merge base plus staged/unstaged/untracked work, intersected with declared scope; policy changes can expand scope. Empty selection is no coverage. Without these selectors, installed quick checks still conservatively cover full declared lint scope. This suggestion changes no defaults and never replaces full completion; TypeScript without `--quick` still typechecks the full tsconfig.

Optional `scb-check` is advisory-only: select it in both `advisory` and `fact.selected_components`, never `required` or `on_demand`. Run the exact `fact.scb_check_command` separately from completion, with declared Python 3.12+ even for TypeScript. Omit that command when unselected; no Python is added to unselected TypeScript use. Native `scb-check.toml` / `[tool.scb-check]` owns rule settings. Follow the [advisory recipe](https://github.com/cheong-yi/gajaestack/blob/main/docs/python-trial.md#optional-advisory-scb-check): review human findings (`1` is not clean), treat errors, missing tools/reports and incomplete-coverage stderr warnings as incomplete even on `0`/`1`, and never infer scan success from status alone. Scan enough project context, review changed-code pertinent findings, and retain justified abstractions rather than forcing rewrites or score targets.

This is explicitly selected soft guidance, not enforcement. Host loading and native guard activation are separate. Preserve existing consumer instructions and configuration; change them only within approved scope. Update shared logic and guidance by upgrading the pinned native dependency, not by editing or re-copying installed files.
