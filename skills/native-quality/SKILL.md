# Native quality checks

Use this skill when selecting or running mechanical repository checks.

- Inspect the repository's documented commands and existing configuration first; required-check labels are not executable names. Prefer the declared entrypoint and tools already adopted there, without repeating checks bound to that entrypoint. Do not add a dependency or change consumer configuration just to standardize tool versions.
- Select only the components and checks that observe the changed behavior, and prune duplicated guidance instead of adding parallel policy. Run formatting separately from lint/type/test checks, and never describe guidance or a command suggestion as an enforcing safeguard. Do not infer pytest from a Ruff-only selection; require it only for selected pytest integration or consumer pytest tests.
- New or noisy checks begin advisory. Make a check blocking only after a representative seeded failure demonstrates the adopted failure behavior—a fails-before/passes-after observation, with the seed reverted afterward and no suppressed warnings or unrelated findings.
- Run optional `scb-check` only when consumer `.gajaestack/routing.toml` selects it in both `advisory` and `fact.selected_components`. Read and use the exact `fact.scb_check_command`; keep completion checks unchanged. Follow the [pinned upstream recipe](https://github.com/cheong-yi/gajaestack/blob/main/docs/python-trial.md#optional-advisory-scb-check) for Python 3.12+ prerequisites (including selected TypeScript use) and native `scb-check.toml` / `[tool.scb-check]` settings. Install nothing implicitly.
- For this advisory, scan enough project scope for clone partners and call-site context, then review findings pertinent to changed code; upstream has no native diff mode. Human CLI output carries detailed findings; JSON carries aggregate metrics only. Retain justified abstractions and boundaries with a reason; never auto-rewrite or chase score targets. Prune the selection when noise and cost outweigh its value.
- Preserve status and stderr: `0` is clean only with intended nonempty coverage, `1` is findings (not clean or infrastructure failure), and documented `2` errors, missing tools, invalid/missing requested JSON, or unexpected failures are incomplete. Upstream can warn and omit failed/malformed ast-grep results even on `0`/`1`; never accept those as clean. Inspect actual `sg` resolution and version, not just the package pin. This is judgment guidance, not fail-closed scan enforcement or proof of an agent trial.
- Keep checks and guidance independently selectable: unselected components add no dependencies or active checks. Apply ordinary host selection acceptance (decision 1A): excluded skills must not be discovery candidates, but GJC diagnostics may expose their names and paths. Loading one selected body does not prove complete model-context isolation.
- For a failure fix, add a focused regression case at the layer that catches the defect, and show it fails with the defect present and passes after; briefly reintroducing the defect is justified evidence when the pre-fix revision is otherwise unavailable. A passing example alone does not prove the check detects the problem.
- Test at the smallest integration boundary that observes the actual contract: public outputs, errors, and important and forbidden effects—not private helpers or call choreography. Choose depth from the change and its risk: unit/property tests for algorithms and distinct cheap edges, end-to-end runs for whole-system risk, and stable reviewed goldens with irrelevant noise normalized only, never blindly refreshed. No coverage or complexity caps, test-count limits, or blanket thresholds.
- Remove duplicate observations only in the affected scope: merge or drop cases that re-observe the same behavior at the same layer, keep those with distinct failure detection, and report the observed runtime of the selection.
- Report exact commands, observed exit/status, exercised runtime, exercised paths and remaining unverified scope. A narrow pass is not whole-repository or host support.

The [selectable native checks guide](https://github.com/cheong-yi/gajaestack/blob/main/docs/python-trial.md) (source repository documentation — open it in the checkout that has it, not assumed present beside this skill) documents the selected check boundaries and their prerequisites. Consumer native configuration and explicit facts selections activate those boundaries; installing a package or reading guidance does not. Mypy/format remain advisory; deeper review and hotspot work stay on-demand.
